# 遥控器、STM32与电机驱动器接线

说明更新：2026-10-14。对应自制STM32F407ZGT6板、HotRC HT-10A遥控器的
F-10A PWM接收器、布瑞特BRT-HDC-D60A双通道有刷驱动器。
无线连接发生在遥控器与接收器之间；接收器用有线PWM信号连接STM32。
ESP-12F（ESP8266）负责Wi-Fi/MQTT网络通信，不传递接收器PWM。
STM32在本地捕获PWM并控制D60A，网页只读查看MQTT状态和输出指令。

## 接收器 → 自制板CN3（5位端子）

| 接收器 | 板端 | STM32 | 用途 |
|---|---|---|---|
| CH1的S信号脚 | CN3-1 / RC_CH1 | PB10 | 右摇杆左右，转向 |
| CH2的S信号脚 | CN3-2 / RC_CH2 | PB11 | 右摇杆上下，前进/后退 |
| CH5的S信号脚 | CN3-3 / RC_CH5 | PF6 | SWA开关，锁定/解锁 |
| ＋电源脚 | CN3-4 / 5V | — | 稳定5V供电 |
| −电源脚 | CN3-5 / GND | — | 与STM32、驱动器共地 |

接收器任意通道的＋/−电源排可用于供电；三路S分别接CH1、CH2、CH5，
不要把S与电源排混淆。端子1脚方向按PCB标识确认，不以照片左/右猜测。

## 自制板CN1（7位端子） → D60A十针控制口

| 板端 | STM32 | D60A控制口 |
|---|---|---|
| CN1-1 / LEFT_PWM | PB6 / TIM4_CH1 | PA，7脚 |
| CN1-2 / LEFT_IN1 | PD6 | A1，8脚 |
| CN1-3 / LEFT_IN2 | PD7 | A2，9脚 |
| CN1-4 / RIGHT_PWM | PB7 / TIM4_CH2 | PB，2脚 |
| CN1-5 / RIGHT_IN1 | PE5 | B1，3脚 |
| CN1-6 / RIGHT_IN2 | PE6 | B2，4脚 |
| CN1-7 / GND | GND | G，5脚或10脚 |

D60A控制口1脚和6脚是5V输出，本接法留空，不接到STM32供电端。
这里的PA/PB是驱动器通道名称，不能当成STM32的GPIO端口。
MA接左电机两根线，MB接右电机两根线。24V只接驱动器功率电源端，
STM32与接收器按板上低压供电设计供电；三者信号地相连。

## 遥控器设置与测试

1. 对频完成后，使用模拟舵机50Hz模式、1000～2000μs脉宽，建议180°角度设置。
   当前代码不支持330Hz数字舵机模式，也不支持SBUS接收器。
2. CH1/CH2用于右摇杆；确认SWA映射到CH5。微调先回中。
3. 先让SWA处于低脉宽的锁定端，摇杆回中保持至少1秒，再拨到高脉宽解锁端。
   现代码以CH5≥1700μs作为解锁条件，哪个实物开关位置对应高端需测一次。
4. 先不接电机观察遥控输入；接电机时抬起底盘，用小幅摇杆验证前后和左右。
   电机安装朝向可能导致实际转向相反，应断电后调整接线或方向配置。
5. 验证SWA锁定、停止及接收器失控保护。接收器如果无线失联后仍持续输出
   原来的有效PWM，STM32的PWM超时检查无法识别这类无线失联；
   应设置并实测接收器失控输出能使底盘锁定。

## 对应工程

- 当前架空测试、保留MQTT网页且不用屏幕：现有24V、5.1A电源优先使用
  `firmware/board_web_link_test_f407/MDK-ARM/board_chassis_web_f407_60pct.uvprojx`，
  固件版本 `mqttmotor60`、最高60% PWM；30%与100%目标仍保留，
  分别为 `mqttmotor30` / `mqttmotor100`。
  三档的工程、HEX和步骤见 `firmware/board_web_link_test_f407/README_MOTOR_WEB_CN.md`。
  PWM上限不是电流限制，也不表示电源已经通过带载验证。
- `board_rc_web_test_f407` 的 `mqttrc1` 为纯模拟，不驱动电机。
- 真正底盘控制工程：`firmware/chassis_f407/MDK-ARM/chassis_f407.uvprojx`。
  这是早期含屏幕的独立工程，不使用当前网页通信。
- 最近的UART4通信测试程序，以及遥控器台架测试程序，不会驱动底盘。
- 当前底盘PWM输出为10kHz：84MHz ÷ (83+1) ÷ (99+1)。
  旧文档的“100kHz，需要改成839”是计算错误，已更正，不要按该旧建议修改。

## MQTT网页联调

开启电脑2.4GHz热点后双击
`.\upper_computer\web_link_host\启动网页联调.cmd`，
使用窗口显示的HTTP 18080网页地址，不直接打开本地index.html。
电脑HTTP仅提供页面/API；STM32使用MQTT 1883，不再使用底盘HTTP直连或/probe。

热点显示ESP已连接不能证明STM32在线。后台发布
`SESSION:<32位小写随机值>`，STM32在新心跳回传后完成双向握手；
在线要求broker正常、`mqttVerified=true`且最新有效心跳年龄不超过5秒。
RAW发布异步等待ESP提示符和发布结果，普通OK或busy不作为成功证据；
超时/断线先隔离迟到响应、恢复串口同步再重连。网页断线会隐藏旧读数，
但本地遥控仍工作；停车用CH5锁定或切断驱动器功率电源。

接线表和软件测试不能替代实体接收器、供电、驱动器与失控保护验证；
下载固件由用户通过ST-Link完成，网页启动脚本不会自动烧录。
